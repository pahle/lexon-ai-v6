# F4.3 Platform Admin Console Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Account status and Provisioning with the Accounts and Organizations console (search, facets, numbered pages, record pages, audited actions, account invitations) built on a shared data views kit.

**Architecture:** Cross-organization reads go through narrow `SECURITY DEFINER` functions in schema `auth` that only `lexon_auth` may execute (spec §3 approach A). A new `PlatformConsoleModule` exposes numbered-page routes through `OrganizationAuthPort.platformRead`; mutations keep `platformTransaction` (2FA plus re-auth). The frontend composes a platform-agnostic kit in `frontend/src/components/data-views/`.

**Tech Stack:** NestJS 12, Better Auth 1.7.14, Zod 4, Drizzle (custom SQL migrations), PostgreSQL 17 with pg_trgm, Next.js 16, shadcn `base-nova`, Vitest 5, Playwright 1.64.1.

**Spec:** `docs/superpowers/specs/2026-11-21-f4.3-platform-console-design.md` (revision 3, owner-approved). Brief: `docs/briefs/F4.3-platform-admin-console.md`. The plan cites spec sections and research notes (§9) instead of repeating them; executors read both.

## Review Focus

1. **A disabled or signed-out admin's other tabs.** After Sign out everywhere, a bearer request and a cookie request for the target both get 401 within the 1 s revalidation TTL (Task 6 test `revoke signs out cookie and bearer sessions`).
2. **A page past the end after a delete.** `page=5` when only 3 pages remain returns `items: []` with the true `total` (companion `_total` query), and the UI moves to the last page rather than showing "No results" (Task 4 `page beyond last returns true total`; Task 11 `out-of-range page moves to last page`).
3. **Search with LIKE metacharacters.** `query=50%_\` matches literally and never widens the result (Task 4 `search escapes % _ and backslash`).
4. **A resend racing an acceptance.** The old token is refused once the invitation is resent; an acceptance that loses the race rolls back the sign-up (Task 9 `acceptance after resend rolls back sign-up`).
5. **A failed fetch rendered as empty.** Every list and record page shows the failure row with Try again, never the empty text (Task 11 `failure never shows the empty text`; Tasks 13–16 per-page failure tests).
