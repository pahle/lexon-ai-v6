# F0 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the four-package, four-runtime developer foundation with executable isolation, durability, compatibility, and topology proofs.

**Architecture:** Four explicit Nest root modules share narrowly exported infrastructure and platform services. PostgreSQL transactions enforce tenant context and processed-job receipts; Testcontainers owns integration infrastructure, while Compose owns topology/E2E. The frontend calls only the backend, and evals boots through one backend evaluation export.

**Tech Stack:** Node 24 LTS; pnpm; TypeScript 6; Zod 4; NestJS 12/Express/ESM; Next.js 16/React 19; assistant-ui 0.15 and AI SDK 7; PostgreSQL 17/Drizzle/pg; BullMQ 6/Valkey 9.0; SeaweedFS 4/AWS SDK v3; Vitest/Testcontainers/Playwright/Stryker; ESLint/Prettier.

**Spec:** [Approved F0 design](../specs/2026-10-31-f0-foundation-design.md), [F0 brief](../../briefs/F0-foundation.md), LEX-TS-001 §2/4–9 and LEX-ARC-001 §2.2/3.2/3.4–3.6/4.1/5.3–5.4/10. Read the spec and this plan together.

## Global Constraints

- Work and commit on `f0-foundation`, never `main`; use execution-time isolation only if needed without changing this branch requirement.
- Clean-room: work from `docs/` and official library documentation; never inspect third-party legal AI source or the `contaminated` branch.
- English everywhere. Exactly four workspace packages: `backend/`, `frontend/`, `shared/`, `evals/`; root is private orchestration.
- ESM-only (`"type": "module"` everywhere); strict TypeScript; backend builds with `tsc`/`nest build`, no CJS shim or Webpack.
- Exactly one TypeScript 6.x and one Zod 4.x, enforced through `overrides` in `pnpm-workspace.yaml`. All pnpm settings live there; exact dependency pins and committed lockfile.
- Node 24 LTS; choose an exact patch satisfying Nest 12 CLI's Node 24 generator minimum. Container images use exact tags and digests.
- TDD: no production behavior before its failing test. Scaffold/configuration bootstrap must establish a runnable test harness before feature behavior is added.
- Only `infrastructure/db` imports `pg`/Drizzle; only `infrastructure/ai` imports model SDK/provider APIs. Frontend keeps approved AI SDK client packages without server model code.
- `evals/` may import only ONE backend evaluation package entry; never backend internals or `infrastructure/*`. Frontend cannot use that exception.
- At-least-once delivery with effectively-once PostgreSQL effects; receipt keyed by outbox ID and effect share one transaction. No claim of exactly-once execution or atomic external effects.
- Integration: one Testcontainers stack per Vitest run, per-file cloned database/Valkey namespace/S3 bucket; no pre-started stack. Reuse opt-in locally, forbidden in CI.
- Workers/dispatcher use application contexts, no HTTP listeners; health files on configurable writable tmpfs, separate liveness/readiness.
- `edge` stays non-internal and host-published ports work. Frontend no-egress enforcement/test is a known F0 gap assigned to F20; frontend stays off `core` and receives no infrastructure secrets. Document-worker no-egress remains mandatory.
- No auth, real models/connectors, chat, F2 layout, F7 document toolchain/encryption, production deployment, or new skill installation.
- Every task starts by reading its listed research notes and checking the selected release's official docs/changelog. Current research was re-read on 2026-10-31; exact package patches are not installed or validated yet. Task 1 resolves the version ledger; later tasks amend it before introducing dependencies. Stop for any locked-stack conflict except the expressly approved BullMQ integration fallback.
- Commands below run from repo root unless stated. Root Vitest projects are named `contracts`, `backend-unit`, `backend-integration`, `frontend`, and `evals`. An `--project`/file selection runs only matching tests; no required empty suite is silently accepted.

## Review Focus

1. Concurrent copies of one outbox job, including a losing transaction whose competitor rolls back: one committed effect and one receipt, no suppressed unfinished work (Task 7).
2. Watch/retry/failed global setup and two integration files running simultaneously: no extra infrastructure stack, shared rows, shared keys, leaked resources, or reused stale template (Task 5).
3. Partial/future/stale health files and an unwritable directory: checker never indefinitely reports healthy from old data (Task 11).
4. Relative imports, aliases, re-exports, literal dynamic imports, and the eval exception used from frontend: same boundary policy as ordinary imports (Task 3).
5. A delayed enqueue response after lease/leadership loss: an old dispatcher cannot mark a new claim sent or continue claiming work; replay still yields one effect (Task 9).
