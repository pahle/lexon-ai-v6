# F4.2 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make F0–F4.1 solid. This means removing retired design material, fixing the listed audit findings, making the chat client cheaper and honest under failure, making the flaky tests deterministic, re-qualifying S2, and sharding CI. There are no new features.

**Architecture:** Six sequential tasks on `f4.2-hardening` (draft PR #46), in the spec's order. Each sub-task is a TDD cycle with RED evidence recorded in `docs/references/F4.2-acceptance.md`.

**Tech Stack:**
- Backend: NestJS 12.3.2, Better Auth 1.7.14, pg 8.23.1, Valkey.
- Frontend: Next.js 16, React 19.3.1, assistant-ui 0.15.33.
- Tests: Vitest, Playwright 1.64.1.
- Tooling: Docker Compose, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-19-f4.2-hardening-design.md` (approved at 7a02f2c). Brief: `docs/briefs/F4.2-hardening.md` (decisions 1–11). "R1a"…"R7" below are that spec's Research notes.

## Global Constraints

- **Dependencies:**
  - pin exact versions;
  - the only new dependency is `eslint-plugin-react-hooks` `7.1.1` (LEX-TS-001 v1.13), with exactly `rules-of-hooks` and `exhaustive-deps` as `error`.
- **TDD:**
  - no production code without a failing test first;
  - RED output tails go into the evidence file, one short record per task;
  - never weaken functional, accessibility, or security assertions;
  - log every changed assertion old → new.
- **Status codes:**
  - a foreign or missing resource stays 404;
  - no response body carries stack, SQL, constraint, or table names;
  - existing error codes keep their meaning.
- **Exit codes:** verify every gate with `rtk proxy <cmd>; echo exit=$?`. Write logs to `.cache/f4.2/logs/<name>.log` and read only `tail -30`.
- **Linux evidence:** required for anything timing-, load-, or visual-related. Use the `mcr.microsoft.com/playwright:v1.64.1-noble` container or CI. Allow at most 2 Linux rounds per area.
- **Docker:**
  - only containers and volumes named `lexon-e2e-*`, by explicit name;
  - never prune, and never `docker rm -f $(docker ps -aq)`;
  - never touch `lexon-dev_*` or the unnamed volume `a4699d7d…`;
  - if disk space or leftover stacks block you, stop and ask the owner.
- **Never** read, print, or commit `.env` or any key.
- **Do not poll CI.** Read each run when it finishes.
- **Copy (verbatim, LEX-DS-001 v3.2):**
  - "Could not copy" (tooltip);
  - "Could not copy. Try again" (accessible name);
  - "Loading this chat…";
  - "Wait for the answer to finish, or stop it.";
  - "Send (unavailable: the chat is loading)";
  - "Send (unavailable: an answer is still arriving)";
  - "We could not load recent chats.";
  - "We could not load members." (pattern: "We could not load <thing>.");
  - "Try again".
- **Budget mode:** an Opus low manager and Sonnet low workers, at most 2 workers in parallel.

## Review Focus

1. **Revoked session while the auth DB is down.** `AUTH_UNAVAILABLE` must not mask revocation forever. Test: auth down for 2 intervals, then revoked → the stream closes within one interval after recovery (Task 2.4).
2. **Tab hidden mid-run, then the run ends while hidden.** On return, one immediate fetch shows the final answer, and there is no smoothing replay of history (Tasks 3.1 and 3.6).
3. **Copy fails, then succeeds.** The state returns to "Copied", not stuck on failed (Task 3.4).
4. **A failed Recent fetch while Chats succeeds, and the reverse.** Each list shows only its own failure (Task 3.8).
5. **A slug race through platform provisioning** and through the org create form at the same moment. Exactly one 201; the other is 409 with the field error (Task 2.1).
