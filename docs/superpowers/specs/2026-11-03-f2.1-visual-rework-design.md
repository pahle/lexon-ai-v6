# F2.1 — Published blocks and Lexon brand

Status: approved by the product owner, with planning notes incorporated. Date: 2026-11-03.
Branch: `f2.1-visual-rework`. Input: `docs/briefs/F2.1-visual-rework.md`.

## Intent and authority

F1/F2 behavior works, but the presentation lost the proportions and composition
of the requested published blocks. F2.1 restores those sources as the visual
authority and applies the Royal Seal brand. Success requires recognizable,
faithful blocks and product-owner screenshot approval, alongside preserved F2
behavior. Passing functional tests alone is insufficient.

LEX-TS-001 v1.10, LEX-ARC-001 §3.5, and LEX-DS-001 v2.0 control this design.
The F2 design, plan, and `docs/references/F2-acceptance.md` define the behavior
that remains. Old DS v1.x presentation rules are superseded, not carried forward.

## Goals, non-goals, and anti-goals

- Rebuild every F1/F2 page's presentation from published `base-nova` blocks,
  shadcn components, and the assistant-ui registry; preserve their geometry.
- Adopt both theme palettes, Inter, Georgia headlines, supplied logos and app
  icons, and the published derived radius scale with `--radius: 0.625rem`.
- Preserve identity lifecycle, route protection, role and tenant enforcement,
  form validation and mutations, organization switching, sign-out, MFA behavior,
  browser-only theme preference, and the inert tenant-keyed local runtime.
- Preserve accessibility, keyboard navigation, first-paint theme behavior,
  reduced motion, and absence of runtime third-party asset requests.
- No new product behavior, routes, endpoints, contracts, model transport,
  suggestions, real auth artwork, marketing pages, or general component library.
- Reject custom resizing/restyling that merely approximates the blocks; reject
  a second sidebar, a logic refactor disguised as visual work, weaker negative
  tests, or screenshot baselines accepted without human visual approval.

## Approaches

1. **Replace presentation inside existing behavior components — selected by
   the product owner.** Start from pristine generated sources, then replace JSX
   and styling while keeping existing handlers/state/providers. Extract only
   repeated published markup, such as the auth frame. This minimizes behavioral
   regression risk and keeps diffs attributable to visual work.
2. **Separate all behavior controllers from views.** Easier isolated view
   inspection, but a broad and unnecessary refactor of proven flows. Rejected
   for this slice.

Behavior code moves only where markup forces it; it is not rewritten. Any
necessary movement is identified in review with the unchanged behavior it
preserves. No parallel component abstraction layer is introduced.

## Responsive interpretation — owner decision

Published blocks keep their responsive classes unchanged. In particular, auth
pages use `lg:grid-cols-2` and `hidden lg:block`: the cover appears from 1024px.
The brief's 768px wording was an authoring error. LEX-DS-001's single 768px
breakpoint applies to layouts Lexon designs and to shadcn mobile behavior
(`use-mobile`, sidebar sheet). This interpretation is not a deviation and has
no deviation-table entry. Do not redefine Tailwind's `lg` breakpoint.

## Brand and themes

Map every light/dark token from DS frontmatter to its §2 shadcn variable,
including the sidebar family, status colors, input/border mapping, and
foreground pairs. Eliminate the old palette and global component-size/type
overrides. Derived radii follow published shadcn output; do not map all radii to
one value. Retain necessary layout tokens such as the 320px right panel without
using them to override published block geometry.

Use Inter through `next/font` at the root; use a Georgia system-serif variable
on auth titles, welcome headline, and settings titles. Keep published font
sizes, weights, and line heights. Reuse next-themes Light/Dark/System behavior,
local preference, inline first-paint script, and CSS-only appearance previews.
No browser request to a font CDN; build-time Inter retrieval is permitted.

Follow `07_DEVELOPER_HANDOFF/INSTALL-NEXTJS.md`: copy supplied public assets,
`LexonLogo.tsx`, and App Router icon/favicon/apple-icon/manifest files. Preserve
the component's asset selection and size-tier logic; change only imports,
lint/format compatibility. Use CSS visibility for ink/cream artwork, never a
client theme branch. No live-font logo, SVG recoloring, or hydration mismatch.
Use compact wordmark at 160px in auth and expanded sidebar, and the supplied
seal-tone micro tile mark in the collapsed sidebar. Keep brand clear space.
Do not enable `dangerouslyAllowSVG`: pinned Next.js automatically serves these
local `.svg` sources unoptimized (Research R4).

## Adaptation accounting

`docs/references/F2.1-acceptance.md` will contain a table with source
block/example, affected Lexon page(s), each markup adaptation, reason,
screenshot/evidence, and approval status. Token values, copy, logo replacement,
data wiring, and removed sample parts are exempt, as the owner explicitly
allowed. Every other markup adaptation is listed, including field changes,
shared-frame extraction, header/group composition, inactive chat controls,
accessibility fixes, and right-panel integration. The breakpoint interpretation
above is exempt, not a deviation.

A change to sizes, spacing, font sizes, radii, or layout structure is never
silently accepted: it needs a written reason and product-owner screenshot
approval. Design approval does not pre-approve an unseen visual departure.
Verified accessibility fixes include the failing check and result after repair.

### Planning-time research additions

Read on 2026-11-03 while writing the implementation plan:

- **R10 — Pristine CSS isolation.** Pinned `shadcn@4.23.0 init --help`
  confirms `--defaults` means Next + base-nova, with `--base`, `--cwd`, and
  `--no-reinstall` supported; `info --json` confirms this project's base-nova,
  Base UI, Tailwind v4, aliases and configured registry. See the
  [official CLI documentation](https://ui.shadcn.com/docs/cli). The planned
  test-only Next fixture lives under `.cache/f2.1-reference/`, obtains its own
  CLI-generated default theme CSS, and mounts generated components through its
  own layout/aliases. Its layout does not import frontend's root layout or
  globals.css. Preserve the generated CSS byte-for-byte in the reference
  evidence. Verify the actual CSS import graph/requests during Task 1; this is
  a researched isolation design, not a claim that the unbuilt harness already
  passed. The [Next Turbopack root documentation](https://nextjs.org/docs/app/api-reference/config/next-config-js/turbopack#root-directory)
  and installed Next 16.4.3 configuration types support a repository-scoped
  root for workspace dependency resolution; module resolution must not pull in
  production layouts/CSS.
- **R11 — Screenshot configuration.** [Playwright visual comparisons](https://playwright.dev/docs/test-snapshots),
  [BrowserContext options](https://playwright.dev/docs/api/class-browser#browser-new-context),
  and [screenshot assertions](https://playwright.dev/docs/api/class-pageassertions#page-assertions-to-have-screenshot-1),
  cross-checked against installed 1.64.1 declarations, support context
  deviceScaleFactor, PNG captures, CSS pixel scale, disabled animations,
  stable snapshotPathTemplate and maxDiffPixelRatio. Plan: dSF1, fixed
  viewports, Linux-generated evidence/baselines and explicit approval mode;
  never regenerate a missing approved baseline during normal CI.
- **R12 — Volatile screenshot data.** [Playwright response modification](https://playwright.dev/docs/mock#modify-api-responses)
  supports `route.fetch` followed by response fulfillment. Existing session UI
  renders `expiresAt` as a localized date; use fixed locale/timezone and
  normalize only this display field in the screenshot fixture's fetched GET
  response. Real auth/role/session identifiers and backend clocks remain
  untouched. Behavior suites never use this normalization. Fixed synthetic
  accounts/teams and loaded-content waits keep other captures repeatable.

- **R13 — Public assets in standalone Docker output.** Read on 2026-11-03:
  [official Next output documentation](https://nextjs.org/docs/app/api-reference/config/next-config-js/output#automatically-copying-traced-files)
  states that standalone does not copy public/ automatically. The existing
  frontend Dockerfile copies standalone and .next/static but omits public/.
  Brand installation therefore needs a minimal runtime public-directory copy,
  proved by a failing then passing real Compose asset request once production
  builds compile. Checkpoint development rendering alone cannot prove this.
  Preserve the pinned images and non-root runtime; use the Docker build skill.
