## 1. Intent

Rebuild every Lexon screen on brand v4.1 and the approved chat experience,
without changing what F0–F4 do. Routes, endpoints, permissions, streaming, and
recovery stay as delivered. The slice ends with an owner-approved screenshot
set locked as Linux CI goldens.

**Goals**

- LEX-DS-001 v3.0 tokens, fonts, and marks everywhere; no Royal Seal color and
  no Georgia-as-headline left in the app.
- The shell, auth pages, new chat page, thread, Chats page, Settings, Platform,
  and error pages match the prototype in layout, hierarchy, content, and states.
- Four behavior additions: Job title, starter pills, floating chat actions, the
  thinking indicator.
- The two flaky F4 tests are root-caused and fixed.
- Goldens locked for the approved set, including replacements for the retired
  F2.1 baselines.

**Non-goals** (brief "Out of scope"): Matters, attachments, legal-quotation
styling, Tabular Review and Editor, Indonesian UI, marketing site, the chat
client state refactor (F5).

**Anti-goals**

- Changing behavior to make a screen look right (shortcut binding, safe error
  and retry, automatic recovery, timing rules for "Thought for" stay as tested).
- Refactoring `chat-runtime.tsx`, `chat-transport.ts`, or `chat-stream.ts`.
- Resizing or restructuring shadcn/assistant-ui components beyond the
  exceptions LEX-DS-001 v3.0 lists (composer, thread width).
- Weakening, skipping, or quarantining a test.

## 3. Approaches

### 3.1 Thinking indicator

| | Approach | Trade-off |
|---|---|---|
| A | Port the prototype's imperative script into a `useEffect` | Fastest. Logic is tangled with DOM and `Math.random`, so the shuffle bag and timings cannot be unit-tested or mutation-tested, and a mid-motion screenshot is not repeatable |
| **B (chosen)** | A pure sequencing engine plus a thin SVG renderer | More files. The engine is deterministic with an injected random source, so it can be tested, mutation-gated, and frozen on a test clock |
| C | CSS keyframes only | No script, but cannot do a shuffle bag, random durations, pattern blending, or finish-from-any-phase |

B is the only one that satisfies the brief's mutation gate and deterministic
screenshot together. The owner delegated implementation choices; this is the
builder's call.

### 3.2 Order of the restyle

| | Approach | Trade-off |
|---|---|---|
| **A (chosen)** | Tokens and fonts first, then shell, auth, chat, Settings, remaining pages, then the screenshot set | Every task is one verifiable change; the app is coherent after task one |
| B | Screen by screen with tokens introduced per screen | Mixed palettes for most of the slice; token guard cannot go green until the end |

### 3.3 Visual baselines

| | Approach | Trade-off |
|---|---|---|
| **A (chosen)** | One new F4.1 set that supersedes the F2.1 and F4 sets; the old comparisons are retired with a recorded owner approval | One source of truth. Needs an explicit retirement record for the 62 still-active F2.1 goldens |
| B | Re-golden the F2.1 and F4 sets in place and add F4.1 extras | Three sets with overlapping states; the F2.1 capture spec carries layout assertions for a shell that no longer exists |

A token change alters every pixel of every existing golden, so no existing
baseline can stay green. This is owner question Q2.

## 4. Design

### 4.1 Tokens, fonts, assets

- `globals.css` gets the v3.0 values for light and dark, the `--lexon-*`
  tokens, and chart colors. The Appearance preview blocks use the same values.
  Legacy aliases (`--surface`, `--surface-raised`, `--primary-hover`,
  `--brand-sage`, `--danger`) are removed, and their consumers move to v3.0
  tokens.
- **Guard:** `scripts/test/design-tokens.spec.mjs` is rewritten to assert every
  v3.0 token in both themes and both preview blocks. It also fails if any
  Royal Seal hex or the word "Georgia" appears outside a font fallback list in
  `frontend/src` or `frontend/public`.
- **Fonts:** files and licenses are copied to `frontend/src/fonts/`. One
  `frontend/src/fonts/index.ts` calls `next/font/local` three times: Inter
  (`--font-inter`, weight `100 900`), EB Garamond roman and italic
  (`--font-garamond`, `adjustFontFallback: 'Times New Roman'`), TeX Gyre Bonum
  regular and bold (`--font-bonum`, `preload: false`, unused until F8).
  `display: 'swap'` for all. `@theme inline` maps `--font-sans`,
  `--font-serif`, and a new `--font-document`.
- **Marks:** the four v4.1 SVGs replace the 54 Royal Seal files in
  `frontend/public/`. `LexonLogo` is reduced to `monogram`,
  `wordmark-compact` (tone `ink` or `white`), and `wordmark`.
- **Icons:** `scripts/generate-brand-icons.mjs` renders the monogram with the
  pinned Playwright Chromium into `favicon.ico`, `icon.svg`, the Apple touch
  icon, and the 192/512 manifest icons. Outputs are committed; the manifest
  colors become White and Ink. No new dependency.

### 4.2 Shell

- `Sidebar variant="inset" collapsible="icon"`; the content card is
  `SidebarInset`. No hard header border.
- **Team switcher:** initials on the ink tile, name, and member count for a
  team; the Lexon monogram and "Personal" for the personal workspace. The
  collapsed sidebar shows only the tile.
- **Groups:** "Tools" with a collapsible "Assistant" (New chat with the
  shortcut hint, Chats). "Recent" with six chats, the per-chat menu, and "View
  all chats". Platform keeps its gate and position after Tools.
- **Footer:** `NavUser` with name and job title, falling back to email.
- **Page header:** non-chat pages keep the trigger and an EB Garamond title.
  Chat pages (`/workspace`, `/chats`, `/chats/[chatId]`) have no breadcrumb:
  the trigger sits top left and the floating pill top right (§4.5).
  `WorkspaceBreadcrumb` is removed where nothing uses it.
- Mobile keeps the sheet and its focus handling.

### 4.3 Auth pages

`AuthFrame` becomes the `login-02` layout. Left: the compact wordmark at 128px
and the form on Surface. Right, from 768px up: the Night cover with the red
rule, the tagline, the EB Garamond statement "Every answer names the article
it rests on, so you can check it yourself.", the white wordmark, and
`lexon-ai.com`. Below 768px the cover is hidden. All eight auth routes and
onboarding use it. Field, password, pending, and alert patterns keep their
behavior.

### 4.4 Chat pages

- **New chat:** an EB Garamond greeting "Good morning | afternoon | evening,
  {first name}" from the browser's local hour (05–11, 12–17, otherwise
  evening), rendered after mount so server and client markup agree. No logo
  and no subtitle. The composer is centered with one row of four pills under
  it and no label.
- **Starter pills:** each is a `Button variant="outline"` that sets the
  composer text to its template, focuses the composer, and selects the first
  bracketed placeholder so typing replaces it. A pill never submits. Template
  text is owner question Q3.
- **Composer (both the new chat form and the thread composer):** 880px wide,
  20px radius, soft shadow, round send/stop button, and the Deep thinking
  pill (`aria-pressed`; pressed uses `--lexon-tint` and `--lexon-red-text`).
  The placeholder is "Lexon is answering..." while a run is active. The two
  composers share class constants in one small module; their logic stays
  separate.
- **Thread:** 880px. Answers have no bubble and no avatar, 16px text with
  line-height 1.75. User messages sit in a `--lexon-user-bubble` bubble. A
  fade sits above the composer; scroll-to-latest appears while streaming.
- **States** follow the prototype screens 12–22: edit (controls inside the
  bubble, Cancel then Send), branch picker, stopped ("Stopped" row above the
  action bar), failure as an `Alert` card with title, safe copy, and Try
  again, reconnecting as an inline status in the thread, and a loading
  skeleton at the top with the composer present.
- **Chats page:** EB Garamond "Chats" title, a primary New chat button, the
  search field, date groups, highlights on `--lexon-tint`, `Empty` for no
  results and no chats.

### 4.5 Floating chat actions

A pill at the top right of chat pages with two ghost icon buttons:

- **New chat (+)**, `aria-label="New chat"`, same navigation as the sidebar
  item.
- **Chat actions (⋯)**, `aria-label="Chat actions"`, a `DropdownMenu` with
  Rename and Delete. It reuses `ChatHistoryActions`, the rename flow, and
  `ChatDeleteDialog`, so the behavior and tests of the Recent menu apply.
  Rename opens a `Dialog` with a `Field` (prototype screen 24). On pages with
  no open chat (New chat, Chats) the ⋯ button is disabled.

Delete follows LEX-DS-001 §2: the menu item is plain text, and the
`AlertDialog` confirm uses the `destructive` variant.

### 4.6 Thinking indicator

Three units, all in `frontend/src/components/chat/indicator/`:

1. **`indicator-sequence.ts` (pure, mutation-gated).** No DOM, no clock, no
   `Math.random`.
   - `createShuffleBag(marks, random)`: each round is the Lexon mark, then
     the other six once each in a shuffled order.
   - `createTimeline(random)`: an iterator of phases with durations:
     draw, hold, dissolve (1.1 s), wander (10–14 s, with pattern switches
     every 3.5–5 s, a 1.6 s blend, and no immediate repeat of a pattern),
     settle, draw. Values come from the prototype script.
   - `phaseAt(timeline, elapsedMs)`: which phase and its progress.
   - `planFinish(phase)`: the steps to reach the filled Lexon mark from any
     phase (already on the Lexon mark: complete and fill; on another mark:
     dissolve, settle, draw, fill; in dots: settle, draw, fill), about 3 s.
   - `createSeededRandom(seed)`: used by tests and the screenshot set.
2. **`indicator-geometry.ts` (pure).** The seven mark path definitions, the
   five dot patterns as functions of dot index and time, easing, and
   interpolation of 26 dot positions.
3. **`ThinkingIndicator.tsx` (client component).** One 20px `<svg>` with a
   fixed box, so there is no layout shift. It runs one
   `requestAnimationFrame` loop that writes attributes through refs; React
   does not re-render per frame. Props: `state: 'running' | 'finished'`,
   optional `seed`. When `state` changes from running to finished it plays
   `planFinish` and stops. When it mounts as finished it renders the static
   mark and starts no loop. The loop stops on unmount and while the tab is
   hidden.

`LexonMark` is the static filled monogram as inline SVG with no hooks, so it
renders on the server.

**Wiring.** `PersistedReasoning` renders the header row:

| Message state | Mark | Label |
|---|---|---|
| Running, no measured duration | Indicator running | visually hidden "Thinking" |
| Running, measured duration and answer text | Indicator running | "Thought for N seconds" (collapsible when a summary exists) |
| Completed or stopped, measured duration | Static mark (finish animation if it was mounted while running) | "Thought for N seconds" |
| Completed, no measured duration | Static mark | none, or "Reasoning" when a summary exists (F4 rule) |
| Failed | Static mark | none |

`running` still comes from `message.status.type` in `thread.aui.tsx`. No change
to the three runtime files is expected; if the finish signal cannot be read
without one, the change is limited to exposing that signal and is reported
before it is made.

**Accessibility.** The SVG is `aria-hidden`. One polite `role="status"` text
per running message says "Thinking" and then "Answer complete". Under
`prefers-reduced-motion: reduce` (read with `matchMedia`, live) the component
renders the static mark and never starts the loop. This satisfies WCAG 2.2.2
because the animation is tied to an activity in progress and stops with it,
and 2.3.3 through the reduced-motion path.

**Performance.** A unit test asserts that advancing frames causes no React
commit. A Playwright trace during a long stream in the existing
`chat-runtime-proof` project is recorded as evidence
(`docs/references/F4.1-indicator-trace.json`: frame count, long tasks, longest
task). It is informational, not a timing gate.

### 4.7 Job title

- **Contract (`shared/`):** `JobTitleSchema` = trimmed string, 1–80
  characters. `ProfileInputSchema` becomes
  `{ name?: DisplayName, jobTitle?: JobTitle | null }` and still requires at
  least one key and rejects unknown keys. `null` clears the value; an empty
  or whitespace-only string is rejected. `SafeProfileSchema` and the identity
  user payload gain `jobTitle: string | null`.
- **Storage:** migration `0038_user_job_title.sql` adds
  `auth.user.job_title text` with
  `CHECK (job_title IS NULL OR (job_title = btrim(job_title) AND char_length(job_title) BETWEEN 1 AND 80))`.
  The Drizzle schema and Better Auth `additionalFields` gain `jobTitle` with
  `input: false`, so only the Lexon profile endpoint can write it.
- **API:** the existing `GET` and `PATCH /identity/profile` and the account
  plugin read and write the field. The user id still comes only from the
  verified session.
- **UI:** Settings → Profile gets an optional "Job title" `Field` under
  Display name ("Shown under your name in the sidebar."). Clearing it sends
  `null`. The sidebar shows it after `refreshIdentity()`.
- **Tests:** validation (trim, 0, 1, 80, 81, whitespace, unknown key, `null`),
  the check constraint directly, cross-user (a session cannot read or write
  another user's job title, including through a `userId` parameter), and
  cross-org (the value is the same in every organization the user belongs to,
  and members of another organization cannot read it through member lists).

### 4.8 Member count (see Q1)

`OrganizationSummarySchema`'s `team` variant gains `memberCount: number`
(integer ≥ 1), counted in the same query that lists the caller's
organizations. It is visible to every member of that team, who can already
open Members. The personal variant has no count.

toasts, `Empty`, and `Skeleton` states take the new tokens and the page-title
style. Destructive triggers outside dialogs become outline buttons with
explicit text.

### 4.11 Flaky tests

Both get a root cause before a fix (systematic-debugging), each as its own
task near the start, because they destabilize every later gate.

- **`chat-scaffold.spec.tsx` regenerate sibling.** Observed so far: progress
  depends on the component's polling, the test waits with real-time budgets,
  and the last `waitFor` calls use the short default. The hypothesis to test
  first is a wait-budget race under full-file load, not a product defect. The
  fix must keep every assertion.
- **`visual-rework.spec.ts` Task 7B Checkpoint C.** The symptom is "theme
  still dark when light is expected". This spec belongs to the F2.1 set that
  §3.3 retires; the root cause is still found and fixed, and the fix is
  carried into the F4.1 capture helper so the new set cannot inherit it.

`ai-step-concurrency.spec.ts` (failed once on PR #31) is not in the brief. It
is left alone; if it fails on this branch it is re-run once and reported.

### 4.12 Screenshot set and goldens

- **Set:** `docs/references/F4.1-visual/` with the same file model as F2.1
  (`captures/`, `capture-manifest.json`, `index.json`, `approval.json`,
  `baseline/`, `baseline-manifest.json`, `deviations.md`). A new Playwright
  project `brand-visual` runs `backend/test/e2e/brand-visual.spec.ts` on the
  Compose stack with deterministic fixtures, a fixed clock, and realistic
  synthetic content with no test markers.
- **Coverage:** every screen and state in the brief's "Screens" list, in light
  and dark, at 1440×900 and 390×844. The index maps each capture to its
  prototype screen and to any F2.1 or F4 capture it replaces, so the 20
  retired baselines each have a named replacement.
- **Indicator frames:** the set passes a fixed `seed` and uses the Playwright
  clock (`install`, `pauseAt`, `runFor`) to capture one mid-wander frame, one
  mark frame, and the finished state. Screenshot `animations: 'disabled'`
  does not affect script-driven animation, so the clock is what makes the
  frame repeatable.
- **axe:** runs on every captured state in both themes in the same project.
- **Approval:** local captures go to the owner for review first. After
  approval, Linux goldens are produced by the CI manual capture path, never
  from macOS images. `approval.json` records owner, date, source commit,
  environment, and one hash per image.
- **M3:** the manifest check fails when an image's hash differs from its
  approved hash, which marks that image and every index entry that references
  it as unapproved until the owner approves again.
- **CI:** the `f2.1-visual-rework` hard-coded refs in `ci.yml` are replaced by
  the current set's paths.

### 4.14 Tests that assert presentation

color that LEX-DS-001 v3.0 changes are updated to the v3.0 value in the same

them. An assertion is never deleted without an equivalent one replacing it.
