# F2.1 — Visual rework: published blocks and the Lexon brand

## Goal

F2 delivered correct behavior (identity lifecycle, route protection, role
gates, themes, accessibility checks) but its interface does not resemble the
shadcn/ui blocks and assistant-ui examples the product owner asked for. F1/F2
rules (44px controls, a Lexon type scale, line-height 1.5 headings, a single
5px radius, an 8px grid) were applied on top of the blocks and changed their
proportions; generic cards replaced the auth blocks; the chat surface was cut
down to a heading and a textarea; and a layout bug collapses the onboarding
card.

F2.1 rebuilds the **presentation** of every F1/F2 page from the published
blocks and examples, **at least 1:1**, and applies the new Lexon brand
(LEX-DS-001 v2.0: Royal Seal palette, logo, Inter and Georgia). **Behavior
does not change.** Every F2 behavior and test stays; only markup, styling,
assets, and copy change.

## Method (mandatory)

### Step A — Pristine scaffold

1. Add the published blocks and examples **without editing them**, with the
   shadcn CLI and the configured registries (`base-nova`):
   - shadcn blocks `login-02`, `signup-02`, `sidebar-07`, and the components
     they pull in;
   - assistant-ui `thread` and `thread-list` from the `@assistant-ui`
     registry, composed as in the assistant-ui default template/example
     layout (read `https://www.assistant-ui.com/docs/cli.md` and the
     examples; record which one you follow).
   Blocks that the CLI installs as pages (for example `app/login/page.tsx`)
   may live at those routes **only in this commit**.
2. Capture **reference screenshots** of the untouched blocks (desktop
   1440×900 and mobile 390×844, light theme) into
   `docs/references/F2.1-visual/reference/`.
3. Commit as `chore(ui): add pristine shadcn blocks and assistant-ui example`.
   This commit is the baseline the review diffs against.

Existing F2 `components/ui/*` files that differ from what the CLI generates
for `base-nova` are **reset to the published version** (F2 changed their sizes,
for example `h-11` buttons). Keep only fixes for real defects, each recorded
with its reason.

### Step B — Adapt (allowed changes only)

Adaptation commits may only:

- set CSS variables in `globals.css` to LEX-DS-001 v2.0 (light and dark), set
  `--radius: 0.625rem`, and add the Inter (`next/font`) and Georgia font
  variables;
- replace sample text, sample data, and the block logo with Lexon copy, live
  data, and the `LexonLogo` component;
- wire the F1/F2 logic (forms, validation, mutations, identity provider,
  organization switcher, sign-out, role gates) into the block markup;
- remove block parts that have no Lexon function (social login buttons,
  "Upgrade to Pro", billing and notification menu items, sample projects);
- add or remove form fields using the block's own field components and
  layout (for example the fields F1's schemas require);
- fix verified accessibility defects (contrast, names, focus), each recorded
  in the acceptance notes.

They may **not** change component sizes, spacing, font sizes, radii, or
layout structure of the blocks. Any deviation needs a written reason in the
acceptance notes and the product owner's approval of the screenshot.

## In scope

### Brand and tokens

1. `globals.css` maps every LEX-DS-001 v2.0 token (frontmatter `colors` and
   `colors-dark`) onto the shadcn variables listed in §2 of that document. No
   leftover default palette.
2. Inter through `next/font` (self-hosted; no runtime request to a font host)
   as the sans font; Georgia system serif for headline text (auth page
   titles, welcome headline, settings page titles).
3. Brand assets from `docs/brand/lexon-2026/07_DEVELOPER_HANDOFF/` installed
   as its `INSTALL-NEXTJS.md` describes: `public/` assets, `LexonLogo.tsx`
   (keep its logic; adapt only lint/format and import style), `app/icon.svg`,
   `app/favicon.ico`, `app/apple-icon.png`, `app/manifest.webmanifest`.
   Check how Next.js 16 `next/image` serves SVG at the pinned version; do not
   enable `dangerouslyAllowSVG` unless the docs require it and you record why.
4. The logo is never retyped as text. Light theme shows the ink artwork, dark
   theme the cream artwork, switched with CSS (`dark:` variants) so there is
   no hydration mismatch.

### Auth pages (login-02 / signup-02)

5. Sign in uses `login-02` as published: two columns, form column with the
   logo at the top (compact wordmark, 160px), cover column on the right.
   Remove the social login button; keep "Forgot your password?" and the
   sign-up link.
6. Sign up uses `signup-02` as published, with the fields F1 requires.
7. The cover column is a **placeholder**: a `bg-muted` panel with no image and
   `aria-hidden`, ready for a later `next/image` swap. It is hidden below
   768px exactly as the block hides it.
8. Forgot password, reset password, verify email, two-factor, accept
   invitation, admin setup, and **onboarding** use the same two-column frame
   and the block's form styling (Field components, button sizes). This also
   fixes the collapsed onboarding card.

### Shell (sidebar-07)

9. The workspace uses `sidebar-07` as published:
   - **Sidebar header:** `LexonLogo` compact wordmark (collapsed: tile mark,
     seal tone, micro tier), then the block's team switcher adapted to F2's
     organization switcher (name, "Personal" label, role as the secondary
     line, pagination, create-team dialog, enrollment-required message).
   - **Main navigation** (the block's collapsible group with sub-items):
     Home; Settings → Profile, Security, Appearance; Organization settings
     (active team only) → Members, Invitations (admin, owner), General
     (owner); Platform (platform admin) → Provisioning, Account status.
   - **Conversations group** in place of the block's projects group:
     "No conversations yet." (assistant-ui thread list, empty).
   - **User menu** (the block's nav-user): initials avatar, name, email;
     items Settings and Sign out only.
   - **Page header** from the block: sidebar trigger, vertical separator,
     breadcrumb (for example `Settings / Security`).
10. The in-page settings section navigation from F2 is removed; the sidebar
    sub-items and breadcrumb replace it. Each page still has exactly one
    `h1`, which may be visually hidden where the block has no visible title.
11. The optional right panel from F2 keeps its behavior (fixed desktop width,
    mobile sheet) and uses the shadcn sheet/sidebar styling.

### Home (assistant-ui)

12. Home is the assistant-ui thread as published, filling the main area:
    welcome state, message viewport, and the complete composer.
    - Welcome headline: "Welcome, {display name}" (Georgia), with the
      example's subtitle replaced by one Lexon sentence.
    - Suggestions are omitted until a later slice defines them (F4/F10).
    - The composer input accepts typing. The **send** control and any other
      control that would start a run or attach a file are visible but
      disabled, each with the tooltip "Chat is coming soon". Use a
      focusable, `aria-disabled` control so keyboard users can reach the
      tooltip; Enter and clicks do nothing.
    - The F2 guarantees stay: inert local runtime, adapter never called, no
      network request, no Route Handler or Server Action.

### Settings and platform pages

13. Profile, Security, Appearance, Members, Invitations, General, and the
    platform pages use shadcn `Card` (header, title, description, content,
    footer) and `Field` components as published, in one centered column.
    F1/F2 behavior, copy for errors, and role gates are unchanged.
