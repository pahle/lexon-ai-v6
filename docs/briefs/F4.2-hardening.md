## Goal

Make F0–F4.1 solid before new features land on top of them. This slice:

- removes retired design material and the code that still depends on it;
- fixes the audit findings that affect users or security;
- makes the chat client cheaper and more honest under load and failure;
- makes the flaky tests deterministic;
- re-qualifies the 500-connection streaming target in realistic conditions;
- shortens CI.

Users see the same screens. They also see clearer failures, smoother streaming, and no 500 errors for ordinary conflicts.

## Users and permissions

There are no permission changes. Every fix keeps F1's organization roles, F4's owner-only chat access, and the platform-admin gates. Status codes become more precise (409, 503 instead of 500, and 503 instead of 404). No response may reveal more than it does today: a foreign or missing resource is still 404.

## Decisions already made (product owner, 2026-11-19)

1. **F4.2 is a hardening slice.** It has no new product features and no new screens.
2. **Legacy design material is removed, not archived in place.** Git history is the archive. Text records of past slices stay: acceptance files, deviations, execution decisions, and approval JSON.
3. **Comparison sheets are not committed.** They are CI artifacts from now on. Goldens and approval records stay in the repository.
4. **The 1 s chat tree polling is fixed here (A-07, A-08), not in F5.** The F4.1 brief listed the "chat client state refactor" for F5. F4.2 takes the polling and leaf-state parts. A larger refactor, if still needed, stays in F5.
5. **Load target unchanged:** S2 means at least 500 concurrent chat SSE connections. It is now proven with distinct sessions, both stream types, and the Compose resource limits.

### Audit findings (backend and security)

6. **A-01 — Duplicate slug returns 409, not 500:**
   - `ORG_SLUG_TAKEN` (409) is added to the shared identity error codes.
   - Better Auth's "already exists" and "slug taken" errors and the `organization_slug_unique` unique violation (23505) map to it.
   - This applies on create, rename, and platform provisioning. The forms show the error inline on the slug field.
   - Tests:
     - each of the three paths;
     - a concurrent create of the same slug that gives exactly one 201 and one 409.
7. **A-02 — Safe error filter keeps precise statuses:**
   - auth-library errors and database errors map to a safe 409 or `AUTH_UNAVAILABLE` 503, including a pool acquire timeout;
   - HTTP exceptions keep their status;
   - the unreachable branch is removed;
   - no internal detail leaks.
   - Tests inject each error class.
8. **A-03 — Trusted proxies:**
   - `AUTH_TRUSTED_PROXIES` is set for the Compose stack, with Caddy on a fixed address or the edge network range, so each client gets its own rate-limit bucket.
   - `.env.example` documents it.
   - Boot fails when the list is empty and local development is off.
   - A Compose test proves that two client addresses get separate buckets.
9. **A-04 — Stream revalidation does not exhaust the auth pool:**
   - The chat invalidation stream revalidates the session about every 5 s, not every 1 s.
   - It uses a short per-(user, session, organization) cache, of about 1 s.
   - A temporary `AUTH_UNAVAILABLE` keeps the stream open and retries instead of closing it.
   - Revocation is still enforced within the revalidation interval. A test proves this.
   - A burst of 500 clients started at once is admitted. Today 461 of 500 and 499 of 500 succeed because the 5-connection auth pool times out after 10 s.
   - The fix may change pool size, queueing, or admission. The spec chooses and records the reason.
10. **A-05 — Stream admission failure is 503:**
    - A Valkey admission failure returns 503 with a safe code, not 404.
    - A missing or foreign chat stays 404.
11. **A-10 — One request-validation path:**
    - Body validation happens in one place.
    - A malformed body is `VALIDATION_ERROR` (400) with field paths.
    - Only unparsable JSON is `INVALID_JSON`.
12. **A-16 — Security tests assert the exact failure:**
    - Every listed `.rejects.toBeDefined()` or bare `.rejects.toThrow()` asserts the expected identity error code or SQLSTATE:
      - organizations settings;
      - two-factor;
      - reauthentication;
      - account flows;
      - AI storage cross-tenant foreign keys.
    - The `AI_OUTPUT_LIMIT` test reads back what it wrote.
13. **A-17 — Missing acceptance tests:**
    - A catalog test fails if any table in the `app` schema lacks `relrowsecurity` and `relforcerowsecurity`.
    - For every `app` table, a session with no tenant context sees zero rows.
    - A bearer token of user A is rejected on the endpoints of a real organization A does not belong to.
    - The slug conflict test (item 6) is included.
14. **A-19 — Secret files ignored everywhere:** `.gitignore` uses `**/.env` and `**/.env.*` with `!.env.example`.
15. **A-22 — Audit definer function documented:**
    - `auth.lexon_append_audit` either becomes `SECURITY INVOKER` or carries a migration comment stating the invariant: direct INSERT is the authority, and the function adds no privilege.
    - The spec chooses one.
    - A test proves that `lexon_app` cannot write an audit row for another organization through the function.

### Chat client

16. **A-07 — Polling only when needed:**
    - The chat tree is fetched every 1 s only while reconnecting or before the first stream frame, and every 5 s otherwise.
    - Polling pauses while the tab is hidden and resumes on focus with one immediate fetch.
    - Every fetch is abortable, and a superseded fetch is aborted.
    - About 5 consecutive failures surface the reconnecting state instead of retrying silently.
    - Fake-timer tests cover each rule.
17. **A-08 — One source for the selected leaf:**
    - The selected branch leaf has one owner. The duplicate copies and the unused sync function are removed.
    - The reconcile fallback is tested.
    - `eslint-plugin-react-hooks` is enabled for `frontend/` with its recommended rules, at a pinned version.
18. **A-09 — assistant-ui contract test:**
    - `frontend/test/assistant-ui-contract.spec.tsx` pins the assistant-ui behaviors Lexon relies on: the import path behind the Regenerate fix, branch pruning, and message ids.
    - A pinned-override comment in `pnpm-workspace.yaml` names this test.
    - An assistant-ui upgrade must keep it green.
19. **G1 — Copy failure is visible:** when the clipboard refuses, the copy button shows a failed state with a tooltip such as "Couldn't copy", and the user can try again. A test covers both success and failure.
20. **G2 — Smooth streaming reveal:**
    - Streamed text is revealed at a steady pace instead of in uneven bursts.
    - It never shows more than has been received, and stops work when it catches up.
    - When the stream ends, the full text shows at once.
    - An answer loaded from history shows in full immediately.
    - Reduced motion shows text as it arrives.
21. **G3 — Cheap scrolling, question at the top:**
    - Scroll and layout state are updated at most once per animation frame during streaming, not per chunk.
    - When a new answer starts, the user's question is scrolled near the top, so the answer reads from its beginning.
    - The scroll-to-latest button appears and hides correctly while the user scrolls away and back.
22. **G4 — Long-conversation stress test (automated):**
    - Setup: a thread of at least 8 long exchanges, a new answer streamed in at least 100 chunks, and 4× CPU throttling.
    - Pass conditions:
      - no React render-loop or maximum-update warnings;
      - no stuck scroll-to-latest button;
      - text matches the stream;
      - the indicator finishes.
    - It runs in CI as an E2E test, not as a manual check.
23. **G5 — The composer explains why it can't send:**
    - "An answer is still arriving" and "The chat is loading" are distinct, announced states, with copy shown near the send button and a matching accessible name.
    - Enter does nothing in either state.
    - Stop still works while history is loading.
    - A whitespace-only paste is ignored, and pasted line breaks are preserved.
    - Copy for these states is proposed in the spec and approved by the product owner.
24. **G6 — Failures are never empty states:**
    - These lists show a failure with Try again (the F4.1 error-row pattern) when their fetch fails, never their empty state:
      - Chats;
      - Recent;
      - members;
      - invitations;
      - sessions;
      - platform lists.
    - Each list has one test for the failure and one for the retry.
25. **G7 — Settings keep the draft on failure:**
    - A failed save in Profile, Appearance, or Organization General keeps what the user typed, shows why it failed, and offers a retry.
    - Only the failed setting reverts. Other saved settings stay.

### Tests, load, and CI

26. **Flaky tests made deterministic (no quarantine, no retries added):**
    - **A-12:** lease renewal test. Use larger lease and delay margins or an injected clock.
    - **A-13:** stale-claim fence test. Warm the connection, or make the publication deadline a constructor option.
    - **A-14:** organizations E2E "Route is already handled". Use tolerant route handlers, `unrouteAll` with ignored errors, and wait for gated handlers before reload.
    - **A-15:** edit-and-regenerate E2E:
      - a unique mock answer per run;
      - wait for the run to finish before Regenerate;
      - a unit test if the race reproduces in the product.
    - Each fix is proven by 20 consecutive passes of the affected test on Linux, recorded once.
27. **S2 re-qualification:**
    - **Run setup:**
      - 500 concurrent connections from distinct users and sessions;
      - a mix of run streams and chat invalidation streams;
      - the Compose resource limits (backend 384 MiB, 0.5 CPU, or the values the spec measures and records);
      - both a 30 s ramp and a simultaneous burst (item 9).
    - **Run on:** the final head, on Linux, with a clean source tree.
    - **Recorded:**
      - admitted connections;
      - p95 first-frame latency;
      - backend memory;
      - auth pool wait.
    - The burst passes at 500 of 500.
    - The load test runs in the `chat-sse-load` workflow on demand and before merge.
28. **CI E2E sharding:**
    - The Compose E2E suite is split into 2 or 3 parallel shards. It takes about 17 minutes today.
    - Each shard runs its own stack.
    - Results and artifacts are merged per run.
    - Visual capture and compare stay deterministic per shard.
    - Measured wall time is recorded before and after.
    - `workflow-gate-integrity.spec.mjs` still passes, and no job uses `continue-on-error`.

## User flows

1. Create an organization with a slug that exists: the slug field says it is taken, and nothing else changes.
2. Two people create the same slug at the same moment: one succeeds, and the other sees the taken message.
3. Copy an answer when the browser refuses the clipboard: the button says it did not copy, and a second try can succeed.
4. Send a long question: the question moves near the top, and the answer streams smoothly below it.
5. Switch to another tab during a run, then come back: the answer is complete or still streaming, and no requests ran while the tab was hidden.
6. Press Enter while an answer is arriving: nothing is sent, and the composer says why.
7. The Chats fetch fails: Chats shows the failure with Try again, not "No chats yet".
8. Save a profile change while the server is down: the typed value stays, the reason is shown, and Try again saves it.
9. The backend briefly loses its auth database during a run: the stream stays open, and the run completes.

## Data and contracts

- `shared/`: `ORG_SLUG_TAKEN` (409) in the identity error codes. `AUTH_UNAVAILABLE` (503) and the stream admission code are used where items 7, 9 and 10 say.
- One migration only if A-22 is changed to `SECURITY INVOKER`.

## Non-functional requirements

- **Security:**
  - No response reveals more than today.
  - Every changed status has a negative test.
  - Rate limiting works per client behind Caddy.
  - Revocation still ends a stream within the revalidation interval.
- **Performance:**
  - Streaming work is batched per frame.
  - The client polls only as item 16 allows.
  - The S2 numbers are recorded at the Compose limits.
- **Accessibility:**
  - New states (copy failed, composer reasons, list failures) are announced and pass axe in both themes.
  - Visual goldens stay unchanged, except where a new state is added. A new state is added to the prototype first (LEX-DS-001 §5.6).
- **Process (standing rules):**
  - TDD with RED evidence per rule.
  - A draft PR from the first task, so CI runs on every push.
  - Never weaken functional, accessibility, or security assertions. Any changed assertion is logged old → new in the evidence.
  - Verify exit codes (`rtk proxy <cmd>; echo exit=$?`).
  - Do not poll CI; read results when a run finishes.
  - Linux evidence for anything timing-, load-, or visual-related.
  - **Docker hygiene:** stop or remove only containers and volumes whose names start with `lexon-e2e-`, by explicit name filter.
    - Never prune.
    - Never touch the `lexon-dev_*` volumes or the unnamed development volume.
    - If disk space or leftover stacks block a gate, stop and ask the owner.
  - **Budget mode:**
    - a low-effort manager with low-effort workers, at most 2 workers;
    - at most 2 Linux-measured rounds per area;
    - batched captures;
    - short tool output, with logs written to files and only their tails read.
  - One short evidence record per task in `docs/references/F4.2-acceptance.md`.
