## Goal

Close the known vulnerabilities and the audit 2 findings that F5 would build on, before F5 adds tools and approvals. This slice:

- upgrades the dependencies behind the 16 OSV-Scanner findings, so the allowlist can be emptied before it expires on **2026-12-22**;
- adds the missing cross-user and cross-organization tests and makes vague assertions exact;
- fixes small error-path, configuration and logging defects, test first;
- makes the chat poll and stream cheaper, which F5's tool and approval states will rely on;
- runs the mutation gates for the security-critical modules.

Users see the same screens. They see one clearer message when something changed under them (item 9), and they never see an authentication error for an outage that is not authentication.

## Users and permissions

There are no permission changes. Every fix keeps F1's organization roles, F4's owner-only chat access, and the platform-admin gates. A foreign or missing resource is still a 404 with the same body as a random id. No response may reveal more than it does today.

## User flows

1. A member renames their organization while an owner deletes it: the member sees "Something changed while you were working. Refresh and try again.", not a generic failure.
2. Valkey restarts while a user opens Chats: the request fails as a temporary outage, never as "Authentication is temporarily unavailable."
3. A user leaves a chat while a poll is in flight: the request is cancelled at once.
4. An idle chat stays open for a minute: the polls do not reload the conversation, and the open answer keeps its text selection while a new answer streams.
5. A user from another organization replays a known chat URL against send, edit, regenerate, viewed-leaf, search-match or delete: they get 404, and nothing changes for the owner.

## Non-functional requirements

- **Security:** every changed status has a negative test. The cross-actor tests use real identities and real HTTP, not mocks.
- **Privacy:** no K1 in logs or errors. The new `errorKind` field is K3. The search terms and the messages stay out of logs (LEX-ARC-001 §6).
- **Performance:**
  - polls of unchanged chats cost no tree query;
  - run streams revalidate every 5 s;
  - streamed Markdown keeps its DOM nodes;
  - the load check records the auth-pool wait.
- **Accessibility:** the 409 message is announced like the error it replaces. No other UI change.
- **Process (standing rules):**
  - TDD with RED evidence per item.
  - A draft PR from the first task. Every report states the CI result of its head.
  - Never weaken a functional, accessibility or security assertion. Log every changed assertion old → new.
  - Verify exit codes. Do not poll CI.
  - Linux evidence for anything timing- or load-related.
  - Work in your own git worktree.
  - **Docker:** only touch containers and volumes named `lexon-e2e-*`, by explicit name filter. Never prune. Never touch the unnamed volume `a4699d7d…` or any `lexon-dev_*` volume. If disk space or leftover stacks block a gate, stop and ask the owner.
  - **Caps:** no visual rounds. At most 2 Linux runs each for the load check and for the 20-pass flake counters. Extra runs need the owner.
  - One short evidence record per task in `docs/references/F4.4-acceptance.md`.
