## Goal

Make three intermittent tests deterministic before F5 adds more chat and identity E2E on top of them. Each fix starts from a proven root cause, not a guess, and ends with 20 consecutive passes on Linux. If a cause is a product bug, the product is fixed test first.

## Decisions already made (product owner, 2026-11-24)

1. **A small slice of its own,** after F4.4 and before F5, so F5's CI is not interrupted by known flakes.
2. **Only the three tests below.** A new flake seen during this slice is recorded with its run URL, not fixed here, unless the owner adds it.
3. **No retries, quarantine, `test.fixme`, skips, or longer timeouts without a proven cause.** Never weaken an assertion; log every changed assertion old → new.

## In scope

Every item starts by reading the failing run's artifacts (Playwright trace, Compose logs, test output) and the code path. F4.4 keeps traces and Compose logs on failure; turn on `trace: 'retain-on-failure'` for the `identity-browser` project too, if it is not already on.

1. **TOTP enrollment E2E** — `backend/test/e2e/account-security.spec.ts:111` ("security TOTP enrollment challenge and recovery are accessible and remain ephemeral").
   - Seen twice: on `72146259` (PR #66, 73/74 passed) and on `2b11b96f` (PR #69, run 45235041821, job `compose-e2e (3/3)`).
   - Symptom: `locator.fill` times out after 45 s at `:238`, waiting for the "Recovery code" field.
   - Find why the field is not there in time: a step that did not finish (a 2FA verify request, a rate-limit answer, a state the page did not reach), or a selector that matches a different element.
2. **Open sign-up setup E2E** — `backend/test/e2e/platform-setup-open-signup.spec.ts:39` ("open sign-up: the setup link creates a platform administrator exactly once and an ordinary sign-up never gets platform rights").
   - Seen on `2b11b96f` (run 45235041821).
   - Symptom: at `:169`, `page.goto('/platform/provisioning')` is interrupted by a navigation to `/workspace`.
   - Hypothesis (to be proven or refuted): the ordinary user's post-sign-in redirect to `/workspace` is still in flight when the test navigates. If so, the test must wait for the redirect to finish (URL and a loaded marker) before navigating. If the app redirects twice, or late, that is a product bug.
3. **AI cancel integration** — `backend/test/integration/ai-cancel.spec.ts`.
   - Seen on `1b055a4c` (run 45213772001).
   - Symptoms: `:786` expected the events `text-end, finish-step, status, finish` but saw `reset, start, status, finish`; `:207` expected `written` but saw `unavailable`.
   - Find which race produces a `reset` frame and an unavailable publish: lease timing, the publication deadline, or test setup ordering.

For each item:

- **Root cause** written down with evidence (trace step, log line, code location). A cause that is not proven stays a hypothesis, and the owner decides whether to continue.
- **RED:** a deterministic reproduction before the fix: injected delay or ordering, a stubbed slow dependency, or a stressed local loop that fails. If none fails locally, record what was tried.
- **Fix** in the test or, when the cause is in the product, in the product, test first. A product fix that changes behaviour visible to users stops for the owner.
- **Linux proof:** one shared 20-pass round for all three tests through `flake-round.yml`, extended to accept these tests. Record 20/20 per test with the run URL.

## Non-functional requirements

- **Process (standing rules):**
  - TDD with RED evidence per item.
  - A draft PR from the first task; every report lists every workflow run on its head with conclusion and URL.
  - Verify exit codes; check `date -u` before any time-based claim.
  - Work in your own git worktree.
  - **Docker:** only touch containers and volumes named `lexon-e2e-*`, by explicit name filter. Never prune. Never touch the unnamed volume `a4699d7d…` or any `lexon-dev_*` volume. If disk space or leftover stacks block a gate, stop and ask the owner.
  - **Caps:** at most 2 Linux flake rounds. No visual rounds.
- **Privacy:** traces and logs used as evidence come from E2E fixtures only; never paste a real `.env` value or key.

- [ ] Any product change is tested first; user-visible changes were approved by the owner.
- [ ] All existing tests pass; CI green on the final head.
