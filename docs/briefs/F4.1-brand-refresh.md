## Goal

Rebuild Lexon's whole interface on the **Lexon brand v4.1** and the chat experience the product owner approved in the F4.1 prototype. Behavior stays as F4 delivered it: the same routes, endpoints, data, permissions, streaming and recovery. This slice changes presentation, interaction feel, and a small set of UI details listed below.

The visual target is `docs/design/f4.1-prototype/` (approved 2026-11-13, revision 12): screens in light and dark, desktop and mobile, a clickable self-contained prototype (`source/prototype.html`), and filmstrips of the thinking indicator. Its README maps each screen to the shadcn or assistant-ui component it is built from.

F4.1 also absorbs **F4 Task 20** (lock Linux visual baselines), creates replacements for the **20 F2.1 baselines retired in F4**, and resolves the F4 visual deviations recorded as F4.1 polish in `docs/references/F4-visual/deviations.md`.

## Users and permissions

There are no permission changes. Every screen keeps F4's owner-only chat access, F1's organization roles, and platform-admin gates. New UI elements (the Personal workspace mark, the floating chat actions, the Job title field) follow the permissions of the data they show or edit.

## Decisions already made (product owner, 2026-11-13)

1. **Brand v4.1** replaces Royal Seal: white surfaces, Ink `#1A1718`, Surface `#F5F4F4`, Merah Segel `#B3202A` used **only** for primary actions and items Lexon flags for checking, Merah Segel Deep `#8E1A22` for the confirm button of destructive dialogs. The kit's `lexon-shadcn-theme.css` gives the light tokens.
2. **Type:** EB Garamond for page headlines (welcome greeting, page titles, dialog section titles), Inter for UI and body, TeX Gyre Bonum reserved for legal quotations (F8 onward). All three are self-hosted from the brand package with their licenses (OFL, GUST).
3. **Dark mode stays.** The dark palette was derived from the kit and approved with the prototype (full list with measured contrast in LEX-DS-001 v3.0 §2): background `#121011`, card `#1A1718`, sidebar `#181516`, muted text `#A69FA1` (7.3:1), red text and focus ring `#F0646C` (6.1:1), primary button stays `#B3202A` with white text (6.65:1).
4. **UI language stays English.** The kit's Indonesian labels map to English: Tools (Alat), Matters (Perkara; arrives with F6), New chat, Chats, Share.
5. **Shell:** shadcn `sidebar-07` in its **inset** form, with the content as a rounded card on the sidebar canvas. The team switcher shows the organization's initials on an ink tile with the member count. The **Personal workspace shows the Lexon monogram**. Groups are **Tools → Assistant** (sub-items New chat, Chats) and **Recent** (six chats, then View all chats). Platform keeps its gate. The user block shows name and **job title**.
6. **No breadcrumb header in chat pages.** The sidebar toggle sits at the top left, and a floating pill at the top right holds **New chat (+)** and **chat actions (⋯)**: rename and delete.
7. **New chat page:** an EB Garamond greeting with **no logo**; the composer is centered; **one row of short starter pills** under it, with no "Try asking" label. Each pill inserts an editable template into the composer and **never auto-sends**. Pill text: Explain an article, Compare two rules, Check a clause, Summarize a regulation.
8. **Thread:** thread and composer are 880 px wide. Answers are reading-first: no bubble, body line-height about 1.75. User messages sit in a Surface bubble. The composer is elevated (soft shadow, 20 px radius) with a round send/stop button, and the **Deep thinking** toggle is a pill (pressed: tint background, red text). A fade sits above the composer, and a scroll-to-latest button appears while streaming.
9. **Thinking indicator: a morphing mark, built in-house** (SVG and code; no third-party assets).
   - Each round starts with the **Lexon monogram** (outline draws, then fills), followed by the other marks, each **exactly once in a shuffled order**: §, Writing (signature stroke), Paper (page with lines), Highlighter (band over lines), Column (courthouse with three pillars catching light), ¶.
   - Between marks the shape un-writes into about 26 dots. The dots wander for **10–14 s**, switching between randomly chosen patterns (scatter, orbit, swarm, spiral, figure-8) every 3.5–5 s with smooth blending, then settle onto the next mark, which draws through them.
   - **When the answer finishes**, from any phase, the motion gathers into the Lexon monogram, which **stays** as a small static mark next to "Thought for N seconds" **on every completed answer**, including old answers when reloaded.
   - `prefers-reduced-motion`: a static mark only. The indicator replaces F4's text-only "Thinking…" treatment but keeps F4's labels and timing rules unchanged (no "Thought for" without a measured duration).
10. **Sign-in and sign-up:** the form on the left, compact wordmark at 128 px; on the right a **Night (`#080606`) cover** with the tagline "The AI workspace for Indonesian legal practitioners" behind a short red rule, and a serif statement. Field errors, password toggle, pending button and form alert keep the LEX-DS-001 §5.1 patterns in the new tokens.
11. **Settings dialog** (sidebar-13) is restyled in the new tokens with EB Garamond section titles. **Profile gains a Job title field** (optional, trimmed, 1–80 characters), shown under the user's name in the sidebar.
12. **Destructive actions:** red is the brand primary, so destructive actions use an outline button with explicit text outside dialogs. Merah Segel Deep is used only for the confirm button inside a confirmation dialog.

## User flows

1. Sign in on the new auth page and land on New chat in the Personal workspace (Lexon mark in the switcher).
2. Click a starter pill, edit the inserted text, and send. The indicator runs (Lexon mark first), the answer streams, and the indicator finishes into the mark beside "Thought for N seconds".
3. Reload a completed chat: the static mark and label render immediately, with no animation.
4. Switch to a team organization: the switcher shows its initials and member count; Recent and Chats show only that organization's chats.
5. Rename and delete the open chat from the floating ⋯ menu.
6. Turn on reduced motion: the indicator shows a static mark only.
7. Toggle dark mode in Settings → Appearance: every screen uses the derived dark palette.
8. Edit Job title in Settings → Profile: the sidebar updates.

## Non-functional requirements

- **Accessibility:** axe passes on every screen and state in both themes. Contrast meets the measured values in LEX-DS-001 v3.0. The indicator is `aria-hidden`, with an accessible status text ("Thinking", "Answer complete"). Focus states use the new ring. Reduced motion is respected everywhere.
- **Performance:** the indicator uses SVG with requestAnimationFrame (or CSS) and never blocks streaming text rendering; prove it with a trace during a long stream.
- **No CDN or remote assets:** fonts and marks are self-hosted.
- **Process (from F4 lessons):**
  - two-phase RED-first per rule, with controller-observed RED evidence in every task report;
  - a targeted mutation gate (Stryker, break 80) for the new pure logic (indicator sequencing and shuffle bag, Job title validation);
  - a draft PR from the first task so CI runs every push;
  - no absolute-latency blocking gates on shared runners.
- **Known flaky tests to fix (from F4):** frontend chat-scaffold.spec.tsx "preserves the regenerated assistant sibling across canonical active and terminal refreshes on an edited branch" (fails ~1 in 2 in full-file runs, also before the F4 fix) and backend/test/e2e/visual-rework.spec.ts:993 Task 7B Checkpoint C (theme still dark when light is expected). Root-cause and fix both; never quarantine.
- **assistant-ui upgrade guard:** the F4 Regenerate fix (importCanonicalTerminalRepository in chat-runtime.tsx) relies on assistant-ui core 0.3.32 import-path behaviour; keep its regression test and re-verify on any assistant-ui upgrade.
- **Verify before push:** run every gate the change can affect before pushing (UI flow changes: Compose E2E; streaming changes: the load layer; visual changes: the screenshot set), not only the nearest unit tests.
- **Concise evidence:** one short record per task (commands, results, commit); no repeated log copies or hash tables. Batch review findings into a single fix round.
- **Agent efficiency:** start a fresh agent session per phase (brainstorming, planning, execution); keep tool output short (logs to files, read tails); avoid polling loops.
