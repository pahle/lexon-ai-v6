## Capture-only normalization decisions

Two macOS captures at the same source/browser revision differed in six paths: Security desktop light/dark, Invitations desktop light/dark, Provisioning desktop light and Profile mobile light. The date text identified volatile API timestamps. Provisioning's skeleton is a readiness defect and must be corrected by waiting for the real loaded state; it is not normalized. Profile's difference was inspected independently: sixteen antialias pixels, maximum channel delta one, confined to rounded input corners (bounding box `[32,555,357,574]`). There was no data, focus or layout change. It was left unmasked and without a product correction; final Linux repeated-capture evidence remains required.
