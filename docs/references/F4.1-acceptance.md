### Task 4A: the F4.1 set reuses the existing index and approval file model

The plan sketched a new index and approval shape. The existing model in `scripts/visual-mode.mjs` (`index.json` with `views` and `viewports`; `approval.json` with one `{ path, sha256, width, height }` per image; `review/` and `baseline/` folders) already performs the same checks, so reusing it meets them with tested code instead of a second implementation: **hash** (`assertApprovedVisualSet` compares every review and baseline file's SHA-256 and PNG size with the approval), **platform** (`validateApprovedRecord` requires a Linux environment, Playwright 1.64.1, locale, and timezone, and update mode requires a Linux CI runner), **approval** (`resolveVisualMode` refuses compare and update unless the status is `approved`), and **M3 invalidation** (new `invalidateRecapturedApproval`: a recaptured image with different bytes loses its approved entry and returns the set to `awaiting-owner`). The F4.1 index adds `state`, `theme`, `prototypeReference`, and `replaces` per view.

### Task 9: the collapsed sidebar opens a menu from the Assistant icon

Prototype screen 32 shows one Assistant icon in the collapsed sidebar. As drawn, that leaves **Chats unreachable without expanding the sidebar**, and an existing E2E test (`chat-history.spec.ts` "workspace navigation order and keyboard access survive collapsed sidebar state") requires both New chat and Chats to stay keyboard reachable when collapsed. The build keeps the single icon and makes it open a small menu (New chat, Chats) to the right, so the screen matches the prototype at rest and both destinations stay two keystrokes away. The test's collapsed section was rewritten for the menu (listed under Task 9 below). The alternatives were: two icons when collapsed (keeps the old test, differs from screen 32), or a plain link to New chat (matches screen 32, drops Chats). Say so if you prefer one of those.
