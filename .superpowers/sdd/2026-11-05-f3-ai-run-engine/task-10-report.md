## Deliverable

- Added migration `0019_ai_operations.sql` only. Migrations `0015`–`0018` were not modified. Operations have composite run/step ownership, forced tenant RLS, stable `(org,run,step,call_occurrence)` identity, result lifecycle constraints, canonical argument hash, and a separate canonical snapshot hash binding tool ID + version + arguments.
- Successful model proposal steps persist read and transactional-write operations in the same caller tenant transaction as the step/job receipt/state and successor outbox. Tool effects, operation result/receipt, job receipt, run/step transition, and next outbox share that caller transaction through `StepCoordinator.commit(transactionWork)`.
- Each operation runs in its own durable continuation step without incrementing model iterations. Reads are persisted with an internal `read` operation mode and require no idempotency registration. Only transactional writes execute; unsupported idempotency-key/reconcile adapters are rejected at registration and execution. Approval-required work remains paused for Task 11.
- Transaction deadlines use PostgreSQL 17.11 `transaction_timeout` configured transaction-locally. On timeout the opaque session is expired, callback signal aborted, checked-out client connection termination observed, session destruction/rollback awaited before callback detachment, and no transaction commit occurs. Non-timeout transactions do not install the timeout-only checked-out-client event listener.
- Results are JSON/UTF-8 bounded with an explicit truncation marker. Results enter next-model history in AI SDK 7 tool-result parts using the durable operation UUID and nonce-fenced content. Stream metadata carries operation IDs only.
- Test effects live only in `backend/src/infrastructure/db/testing/ai-fixture.ts`. The real SIGKILL worker is compiled by the shared process-test source loader and pauses after the combined operation/step/job/outbox commit before acknowledgement; redelivery returns the stored operation result and leaves exactly one effect.

## Research

Research notes were added to the F3 design in `docs/superpowers/specs/2026-11-05-f3-ai-run-engine-design.md` before implementation. Verified against official exact-version docs and installed packages:

- PostgreSQL 17.11 [runtime client configuration](https://www.postgresql.org/docs/17/runtime-config-client.html) and [SET](https://www.postgresql.org/docs/17/sql-set.html): `statement_timeout` is per statement; `transaction_timeout` terminates a transaction's backend session and rolls back the transaction. Integration tests observe `25P04` and verify the checked-out session lifecycle.
- `pg@8.23.1` [client API](https://node-postgres.com/apis/client) and installed `lib/client.js`: private `Client.cancel` was not used; timeout handling observes the checked-out client error and destroys the dead client only for bounded transactions. The package has no bundled changelog.
- AI SDK [tool calling](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling) and [generating text](https://ai-sdk.dev/docs/ai-sdk-core/generating-text), installed `ai@7.0.159` bundled docs/declarations/CHANGELOG: proposal and result history preserve the SDK's nested `tool-call` / `tool-result` message part shape; the engine owns durable sequencing.
- Node 24.22.1 [crypto API](https://nodejs.org/download/release/v24.22.1/docs/api/crypto.html): built-in SHA-256 and UUID APIs cover canonical argument/snapshot hashes and stable operation IDs without new dependencies. The existing `canonicalOperationHash` binds the full tool ID, version, and args snapshot.
