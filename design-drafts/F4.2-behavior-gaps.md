# Behavior gap analysis for F0–F4 (dirty side, 2026-11-16)

Prepared on the brief-generator branch only. It compares user-visible behavior of the
reference product with Lexon F0–F4 (main at f3054b7 plus the F4.1 branch). It records
behaviors and ideas in our own words. It contains no code, identifiers, schema, prompts,
or UI text from the reference, and nothing here may be passed to implementers except as
plain-language requirements inside a brief.

## Proposed for F4.2 (small, high value, F0–F4 scope)

| # | Behavior | Lexon today | Why it matters |
|---|---|---|---|
| G1 | When copying an answer fails (the browser refuses clipboard access), the user is told it did not copy and can retry. | The copy action silently does nothing on failure (copy hook ignores the rejection). | A lawyer who pastes an empty clipboard into a document loses trust; silent failure is a defect. |
| G2 | Streamed answer text appears at a steady pace instead of in uneven bursts as chunks arrive; when the answer finishes, or an answer is loaded from history, the full text shows at once. | Text renders exactly as chunks arrive. | Smoother reading during long answers; no effect on stored content. Fits the chat client hardening task. |
| G3 | Streaming stays cheap: the thread does not re-measure layout or recompute scroll state on every chunk; scroll work is batched per frame. When a new answer starts, the user's question is positioned near the top so the answer is read from its beginning. | To verify in the F4.2 spec (F4 review found per-second full-tree polling; scroll behavior during streaming not reviewed). | Long answers on slower laptops; reading from the start is better for legal text. Fits the chat client hardening task. |
| G4 | Every list or fetch failure is shown as a failure with a retry, never as an empty state (for example, a failed invitations or chats lookup must not read as "nothing here"). | To verify per screen in F4.2 (audit theme). | An empty state on failure misleads the user into thinking data is gone. |

## Not adopted (by existing owner decisions)

- Model picker and bring-your-own-key provider keys (owner decided on a fixed model and Deep thinking toggle).
- Two chats side by side; loading another chat in place from a chat header menu (Recent and Chats cover navigation).

## Parity already present in Lexon

Pending invitations during onboarding with retry and expired handling; role-based organization settings sections; safe error copy on failed runs; reconnect and recovery of streams; permanent chat deletion.
